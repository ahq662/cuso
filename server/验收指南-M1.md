# M1 用户认证模块 — 验收指南

> 目标：确认 5 个接口 + 各类异常场景全部符合预期。
> 环境：Windows + Node 24，项目目录 `<项目根目录>\server`

---

## 1. 验收前确认

在 PowerShell 里执行：

```powershell
node -v
```

应显示 `v24.x.x`。再确认目录存在：

```powershell
cd server
dir
```

应能看到 `src`、`test`、`package.json`、`node_modules`。

> 说明：你的机器 PowerShell 禁止运行 `npm.ps1`，所以**不要用 `npm start`**，直接用 `node` 启动即可。

---

## 2. 启动服务（终端 A）

```powershell
cd server
node src/index.js
```

看到下面两行即启动成功：

```
CUSO server listening on http://0.0.0.0:3000
[warn] 正在使用默认 JWT_SECRET，仅用于本地开发；上线前请设置环境变量 JWT_SECRET
```

> 这个 warn 是**正常提示**，本地练手不用管。
> **保持终端 A 不要关**，服务要一直跑着。

---

## 3. 自动化验收（终端 B，推荐先做这个）

新开一个 PowerShell 窗口：

```powershell
cd server
node test/m1.test.js
```

**通过判据**：最后一行是

```
RESULT: pass=30 fail=0
```

并且上面每一行都以 `PASS` 开头。只要出现任何 `FAIL` 或 `fail=0` 以外的数字，就说明没通过。

这一步会覆盖：正常注册/登录/获取资料/改昵称/传头像，以及重复用户名、错密码、无 token、伪造 token、非法 JSON、非图片上传等异常场景。

---

## 4. 手动验收（可选，用 Postman 更直观）

如果你装了 Postman，按下面逐条发请求核对。**建议先做 4.2 注册，把返回的 token 记下来**，后面带鉴权的接口都要用它。

### 4.1 健康检查

- 方法：`GET`
- URL：`http://127.0.0.1:3000/api/health`
- 期望：状态 200，返回 `{"ok":true,...}`

### 4.2 注册

- 方法：`POST`
- URL：`http://127.0.0.1:3000/api/auth/register`
- Body → raw → JSON：

```json
{ "username": "zhangsan", "password": "123456", "nickname": "张三" }
```

- 期望：状态 **201**，返回 `token` 和 `user`；`user` 里**不含** `password_hash`。
- 把返回的 `token` 复制下来。

### 4.3 重复注册（异常）

- 同样的 Body 再发一次
- 期望：状态 **409**，`{"error":"用户名已被占用"}`

### 4.4 密码错误登录（异常）

- `POST http://127.0.0.1:3000/api/auth/login`
- Body：

```json
{ "username": "zhangsan", "password": "wrong" }
```

- 期望：状态 **401**

### 4.5 正确登录

- `POST http://127.0.0.1:3000/api/auth/login`
- Body：

```json
{ "username": "zhangsan", "password": "123456" }
```

- 期望：状态 **200**，返回 `token`

### 4.6 获取当前用户（带 token）

- `GET http://127.0.0.1:3000/api/auth/me`
- Headers：`Authorization: Bearer <你的token>`
- 期望：状态 **200**，`user.username = "zhangsan"`

### 4.7 无 token 访问（异常）

- `GET http://127.0.0.1:3000/api/auth/me`（不带任何 Header）
- 期望：状态 **401**

### 4.8 伪造 token（异常）

- `GET /api/auth/me`，Header：`Authorization: Bearer bad.token.value`
- 期望：状态 **401**

### 4.9 修改昵称

- `PUT http://127.0.0.1:3000/api/auth/profile`
- Headers：`Authorization: Bearer <你的token>`
- Body：

```json
{ "nickname": "新昵称" }
```

- 期望：状态 **200**，`user.nickname = "新昵称"`

### 4.10 上传头像

- `POST http://127.0.0.1:3000/api/auth/avatar`
- Headers：`Authorization: Bearer <你的token>`
- Body → **form-data**：key = `avatar`，类型选 **File**，挑一张 png/jpg 图片
- 期望：状态 **200**，`user.avatarUrl` 形如 `/uploads/avatar_1_....png`
- 浏览器打开 `http://127.0.0.1:3000` + 这个 `avatarUrl`，能看到图片即成功。

## 5. 验收判据（一眼看结果）

| 方式 | 通过标准 |
|------|----------|
| 自动化 | 最后一行 `RESULT: pass=30 fail=0`，全程无 FAIL |
| 手动 | 上面每一步状态码与期望一致 |

---

## 6. 停止服务

回到**终端 A**，按 `Ctrl + C`。

---

## 7. 验收后可选：查看落库结果

- 数据库文件：`server/data/cuso.db`（用 DB Browser for SQLite 打开可看到 `users` 表和注册的用户）
- 头像文件：`server/uploads/` 目录下能看到上传的图片

> 自动化测试每跑一次会新增测试用户（用户名带时间戳），不影响使用。想清空可停服务后删除 `server/data/*` 和 `server/uploads/*`。

## 8. 出问题怎么反馈给我

把这三样发我，我就能快速定位：

1. 哪一步、期望什么、实际发生什么（截图或状态码）；
2. **终端 A** 里服务端打印的报错；
3. 自动化测试里的 `FAIL` 行。

---

## 9. 常见问题

| 现象 | 原因 / 解决 |
|------|-------------|
| 启动报 `EADDRINUSE` | 3000 端口已被占用，说明已有服务在跑，先关掉旧的 |
| `npm` 报 `PSSecurityException` | 你的 PowerShell 禁了 npm.ps1，改用 `node src/index.js` 或 `npm.cmd` |
| 测试连不上服务 | 确认终端 A 已启动且显示 listening |
| 上传头像返回 400 | 确认选的是图片文件，且 form-data 字段名必须叫 `avatar` |
| 打开头像 URL 404 | 确认服务在跑；相对路径要以 `/uploads/` 开头拼到 `http://127.0.0.1:3000` 后面 |
